# Findings — 2026-09-23 session

Empirical rules extracted from tonight's runs. Each is backed by numbers in [measurements/](../measurements/).

1. **Decode speed is prompt-dominated, not flag-dominated.** Same prompt, batch defaults vs `-b 512 -ub 512`: 113.7 vs 112.8 tok/s. Same flags, repetitive-continuation prompt vs novel prose: 182 vs ~117 tok/s. The mechanism is MTP draft acceptance (1.00 vs ~0.5–0.75). Rule: **compare across machines only on the same prompt file** (use [prompts/code-continuation.txt](../prompts/code-continuation.txt)); treat "fast" leaderboard numbers from unspecified prompts with suspicion.

2. **Context allocation is free until you fill it.** 4B @128K decodes the same 182 tok/s as @32K (181.8) at short fill; 9B @64K matches @32K (124.x both). The size you allocate costs VRAM, not speed. What costs speed is filled length + MTP acceptance decay (78.8 tok/s at 37K filled on 9B).

3. **The 9B context ceiling on 8 GB is a KV-quant decision, not a model decision.** 9B @64K: q8_0 KV OOMs at load; q4_0 KV fits in 7.27 GB with 524 MiB spare and **zero decode penalty at short fill** (124.2–124.4 vs 124.5–124.8 tok/s). Flash-attention hides the dequant. Prefer bigger-context + q4_0 KV over smaller-context + q8_0 on this card for the 9B.

4. **Windows→Linux parity is exact.** Era-matched build (b10481) on the same card, same flags, same prompt: 173.3–173.6 tok/s vs the Windows lab's 172.3–173.5 — a tie at ±0.1%. Docker adds nothing measurable (server-reported rates; GPU is passed through natively). Migration cost for the lab: zero. Current build (b11118) is the actual upgrade: +5% (4B) to +7% over b10481, and the long-context probes were not possible in the old lab's formats.

5. **Cold start and first-request behavior are real and separate.** ~52–57 s from `docker run` to "model loaded"; the first decode request then pays CUDA-graph compilation (17 tok/s visible in logs) before steady state. Report warmed numbers for speed claims; report both when cold-start latency matters.

6. **Thinking default.** Qwen3.5 MTP templates enable thinking by default; for deterministic coding/agent use send `chat_template_kwargs {"enable_thinking": false}`. Capability note: the 4B fails a multi-fact reasoning comparison with thinking off, the 9B passes it.

7. **Tools work through plain llama.cpp + any agent client.** OpenAI tool calls with round-tripped results verified directly, and independently by opencode's build agent (bash tools executing `free -h`, `lscpu`) against the same server via T3 Code.
