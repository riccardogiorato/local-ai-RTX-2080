# Findings — 2026-09-24 (overnight batch: kev, laya, Gemma 4 E4B QAT, MiMo 9B)

1. **HF `hf download` hangs silently on xet CAS stalls** — zero bytes/min with no error and no
   exit, so retry loops never fire. `HF_HUB_DISABLE_XET=1` fixes it, but `hf` also uses a **new
   `.incomplete` file per attempt** (no cross-attempt resume), so any timeout-guarded retry
   loop discards progress. Working pattern for this machine: plain `curl -L -C -
   --speed-limit 8192 --speed-time 120` on the `resolve/main` URL — real HTTP-Range resume
   plus curl's own stall detection. Verify size + sha256 against `/api/models/<repo>/tree`
   LFS oids (they are the sha256).
2. **Gemma 4 E4B is a MatFormer-class (effective-params) model with KV layer sharing**
   (layers 0–3 share K/V with 40–41): a 4.22 GB tensor file runs ~2.9 GB GPU-resident, and
   **128K context fits with the drafter at 5.81 GB total** — the largest resident context
   measured on this card (Qwen3.5-9B tops at 64K).
3. **Gemma 4 E4B needs its thinking mode for reasoning** — with `enable_thinking:false` it
   answers deterministic-but-wrong ("same" on the trains probe it gets right with thinking,
   in 1.9 s total). Same kwarg key as Qwen under `--jinja`. Budget ≥ 500 tokens or content
   comes back empty (reasoning eats the cap first).
4. **The first request after any llama-server fresh load pays ~25–50 s of CUDA-graph
   compile** and its "prompt eval" rate line is garbage (86 tok/s on Gemma, 52 on the 9B
   control). Only the *second* request's server timings are real; measures after that are
   stable. (Generalizes yesterday's 17 tok/s note: never time request #1.)
5. **Xiaomi's MiMo distill drops the parent's nextn/MTP head from its GGUF** — `draft-mtp`
   refuses to load ("model doesn't contain MTP layers"). Head-to-head with a Qwen3.5-9B
   no-draft control: 61 vs 62 tok/s — **identical**: the distill costs zero per-token speed;
   all of the 2× decode gap to the parent is the missing drafter.
6. **Two "typed decision" models, two very different trade curves** (same /v1/systemone
   wire protocol): kev-0.5b 146 MiB / 240 ms / routes both probes to intent; laya 2.66 GB /
   27 ms / coin-flip on the ambiguous probe. On an 8 GB card the VRAM dominates — kev is the
   one that composes with a resident LLM; laya is the one for a dedicated routing box.
7. **`laya-serve --help` never prints** (startup hooks block before argparse); launch
   directly and poll `/health`. kev's server binds **8008**, not the 8009 in the README
   quickstart.
